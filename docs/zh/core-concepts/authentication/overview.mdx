使用 InsForge 身份验证来处理您的应用程序的注册、登录、会话和身份。用户可以使用电子邮件和密码、魔法链接、一次性代码、OAuth 提供程序（Google、GitHub、Apple 等）或您自己的任何符合 OIDC 的身份提供程序进行登录。InsForge 在登录时发出 JSON Web Token，平台上的每个其他产品都使用相同的令牌。

  <img src="/images/authentication-methods.png" alt="InsForge 仪表盘身份验证方法显示电子邮件和密码、Google OAuth 和 GitHub OAuth" />

<Note>
  **身份验证**是检查用户是否就是他们所声称的人。**授权**是检查他们可以做什么。InsForge 直接处理前者，并通过读取身份验证 JWT 的 [行级安全](/core-concepts/database/overview) 策略来增强后者。
</Note>

## 功能

### 电子邮件和密码

默认值。新用户使用电子邮件和密码注册，收到确认电子邮件，并在登录时接收会话 JWT。密码重置、电子邮件验证和暴力破解限制都是内置的。

<Note>
  **自托管？** 发送这些电子邮件，包括无密码的魔法链接和一次性代码登录，都需要电子邮件服务商。已连接云的项目会自动使用托管发件服务；自托管实例必须先配置 [Custom SMTP](/core-concepts/messaging/custom-smtp)，否则验证、重置和登录邮件都无法送达。
</Note>

### 魔法链接和一次性密码

向用户的电子邮件发送一次性链接或六位数代码。无密码登录、账户恢复和步进身份验证都使用相同的基础。

### OAuth 提供程序

对 Google、GitHub、Apple、Microsoft、GitLab、Discord 等的一流支持。通过 URL 添加自定义 OAuth 2.0 / OIDC 提供程序（Keycloak、Okta、Auth0、您自己的 IdP），无需编写特定于提供程序的代码。

#### 将提供程序关联到现有用户

您无需单独的账户关联步骤。当有人使用 OAuth 提供程序（例如 Google）登录，且该提供程序返回的电子邮件与现有用户匹配时——无论该用户是通过电子邮件和密码创建的，还是通过其他提供程序创建的——InsForge 都会自动将新身份关联到现有账户。它会在 `auth.user_providers` 中记录该提供程序，将电子邮件标记为已验证，并以同一账户身份登录该用户。不会创建重复用户，也不会返回错误。

要让您的现有用户开始使用 Google 登录，请在仪表板的 **Authentication → Auth Methods** 下启用 Google 提供程序。下次用户使用与其现有账户相同的电子邮件通过 Google 登录时，该 Google 身份会关联到他们的用户，并保留相同的用户 ID 和数据。

<Note>
  关联完全基于提供程序声明的电子邮件地址进行匹配，因此请仅启用您信任其会验证电子邮件所有权的提供程序。项目级别的注册开关仅阻止全新用户：即使在禁用新注册的情况下，电子邮件与现有账户匹配的登录仍会被关联并登录。没有内置端点可在不进行全新 OAuth 登录的情况下将提供程序关联到已登录的会话，也没有端点可取消关联。
</Note>

### OAuth 服务器模式

将 InsForge 本身作为 OAuth 2.0 / OIDC 身份提供程序运行，用于您自己的下游应用程序。有关完整设置，请参阅 [OAuth 服务器指南](/oauth-server)。

### 行级安全

身份验证 JWT 自动流经每个 InsForge SDK 调用。Postgres RLS 策略从令牌读取声明，并逐行决定用户可以读取和写入的内容。无论请求命中数据库、存储还是实时通道，相同的身份和相同的策略都适用。

### 数据库中的 `auth.users`

用户状态存在于项目的 Postgres 数据库中的 `auth` 架构中。通过外键将 `auth.users` 连接到您的应用程序表，通过触发器对身份更改做出反应，并以与备份其他所有内容相同的方式备份整个事物。
