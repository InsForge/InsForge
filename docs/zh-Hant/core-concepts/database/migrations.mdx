遷移是 `migrations/` 中應用於 `@insforge/cli` 的版本化 SQL 檔案。每次成功執行都記錄在 `system.custom_migrations` 中。工作流程是僅向前的。

## 概念

遷移是一個帶有 14 位數 UTC 時間戳前綴的 SQL 檔案：`<YYYYMMDDHHmmss>_<name>.sql`。CLI 在交易內按順序應用待處理檔案，將 `search_path` 設定為 `public`，並僅在成功時記錄歷史。PostgREST 自動重新載入架構中繼資料。檔案內的 `BEGIN`/`COMMIT`/`ROLLBACK` 被拒絕。

## 用法

連結後端，然後建立檔案。

```bash
npx @insforge/cli login
npx @insforge/cli link
npx @insforge/cli db migrations new create-employees-table
```

編寫 SQL。

```sql
create table if not exists public.employees (
  id bigint primary key generated always as identity,
  name text not null,
  email text,
  created_at timestamptz default now()
);
```

應用待處理的遷移並檢查歷史。

```bash
npx @insforge/cli db migrations up --all
npx @insforge/cli db migrations list
```

使用 `up <version>` 針對單個檔案，或使用 `up --to <version>` 應用到目標為止的所有待處理項。

## 特定用法案例

在現有專案上採用遷移：首先執行 `db migrations fetch` 來將遠端歷史具體化為本機檔案。一旦應用於遠端，永遠不要就地編輯遷移。改為編寫前向遷移。

選擇加入後，透過檔案路由所有架構變更。臨時儀表板編輯會在 git 和 `system.custom_migrations` 之間造成漂移。

## 無法在交易中執行的陳述式

由於每個遷移檔案都在單一交易內執行（參見[概念](#概念)），少數 PostgreSQL 只允許在交易區塊*之外*執行的命令在放入遷移時會失敗。你會看到類似 `CREATE INDEX CONCURRENTLY cannot run inside a transaction block` 或 `VACUUM cannot run inside a transaction block` 的錯誤。常見的有 `CREATE INDEX CONCURRENTLY`（以及 `DROP INDEX CONCURRENTLY` / `REINDEX ... CONCURRENTLY`）、`VACUUM` 和不帶參數的 `CLUSTER`。

有兩種處理方式：

- **在存在普通交易內形式時優先使用它。** 普通的 `CREATE INDEX`（不帶 `CONCURRENTLY`）可以在遷移內執行，並使變更保持版本化和可重現。它在建立索引時會持有更強的鎖，因此只有在繁忙資料表上無法承受該鎖時才使用 `CONCURRENTLY`。
- **在遷移之外執行非交易性陳述式**，使用 `db query --unrestricted`，它將單一陳述式傳送到資料庫而不將其包裹在交易中：

```bash
npx @insforge/cli db query --unrestricted "CREATE INDEX CONCURRENTLY idx_employees_email ON public.employees (email)"
```

普通的 `db query`（不帶 `--unrestricted`）仍在交易內執行，因此這些命令需要 `--unrestricted`。由於這會繞過遷移歷史，請自行保持各環境同步——記錄該手動步驟，或在所有環境中執行等效陳述式。

`VACUUM` 通常由 PostgreSQL 的 autovacuum 常駐程式處理，很少需要手動執行；當你確實需要時，以同樣的方式執行：

```bash
npx @insforge/cli db query --unrestricted "VACUUM (ANALYZE) public.employees"
```

原始 SQL 以 30 秒的陳述式逾時執行，因此在非常大的資料表上進行 `CONCURRENTLY` 建立或 `VACUUM` 可能會逾時。對於長時間執行的維護任務，請使用 `psql` 等用戶端連接到專案的 Postgres 連線字串（`npx @insforge/cli db connection-string`，僅限雲端專案——參見 [FAQ](/faq)），並在那裡執行該陳述式。
